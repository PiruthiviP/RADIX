11. Orchestration Graph (app/graph.py)
Create the core LangGraph state machine using StateGraph.

WorkflowState (TypedDict):
Tracks: admin_data (dict), temperature (float), max_retry_rounds (int), strict_grounding_regeneration (bool), schema_totals (dict), missing_fields (list), research_docs (list), research_context (str), batch_plan (dict), provider_datasets (dict of dicts), provider_stats (dict), consolidated_sources (dict), final_profile (dict), generation_status (str), progress_callback (callable).
Nodes & Edges Layout:
__start__ -> validate_input -> load_schema -> detect_missing -> collect_research -> build_context -> plan_batches -> generate_with_retry -> consolidate -> __end__.
Node Logics:
validate_input: normalizes parameters provided in the request according to the admin schemas.
load_schema: loads total schema metrics from SchemaManager.
detect_missing: identifies which of the 13 admin grounding inputs are empty or missing.
collect_research: queries ResearchEngine to gather external files/data.
build_context: builds context string for prompting.
plan_batches: retrieves batch layout from SchemaManager.
generate_with_retry (Batch Generation & Local Retry Loop):
Pre-initializes provider datasets with the grounded admin inputs, mapping all generated fields to "NA".
Creates an execution plan. If strict_grounding_regeneration is true, prepends a grounding validation step for the admin fields. Then appends the 6 generated batches.
For each batch, prompts all LLM adapters in parallel.
Inside the batch loop, runs a retry loop up to max_retry_rounds (default 2):
Prompts the LLM with the list of requested fields, admin variables, and research context.
Parses the LLM's raw text response to JSON (stripping markdown code blocks).
Updates the provider's local dataset with values returned.
Runs the complete dataset validation.
Identifies fields that failed validation. If there are failed fields, runs the next retry attempt requesting only the failed fields.
After retries are exhausted, any remaining invalid fields are locked to "NA".
Returns updated provider datasets and statistics (accepted fields, failed fields, retries used).
consolidate (Consensus and Fallbacks):
For each of the generated fields, pulls the values output by all active providers.
Resolves consensus:
Majority Vote: If 2 or more providers agree (case-insensitive, ignoring spacing, excluding "NA" values), select that value.
Single Non-NA Fallback: If only 1 provider returns a non-"NA" value, select that value.
Research Consistency Overlap: If all providers differ, calculate the token overlap (words length >= 3) between each provider's value and the scraped research_context. Select the value with the highest token overlap percentage.
If no criteria are met, default to "NA".
Maps the selected value to final_profile and records the winning LLM provider in consolidated_sources.
